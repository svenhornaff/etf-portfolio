# ETF Portfolio Report v3 — Refactor Concept

Base: the pushed report `report-2026-10-05.html` (v2) · 2026-10-06 · Target: one standalone HTML, German UI, generated by `uv run etf-portfolio`

## 1. Diagnosis of v2

v2 is correct-ish and complete-ish, but it is a **cockpit, not a report**. Every number has the same visual weight. Nothing tells you what matters. The page is about 8.000 px long, and the sell list, coverage table and VAP checks get as much space as your performance.

The numbers already carry a strong story that the page never states:

| Signal in v2 data | Value | What the report should say |
|---|---|---|
| Gain / XIRR | +8.283 € / 20,4 % p.a. | Good absolute result |
| TWR vs benchmark | 40,6 % vs 34,3 % (Δ +6,3 pp) | Beat the benchmark, but see the estimate warning below |
| Concentration | Top-3 = 90,8 %, largest 41 % | Highly concentrated |
| Thematic share | Semis + Quantum ≈ 34 % | Large satellite share, no core/satellite split shown |
| Turnover 12M | 564 % | This is a trading account, not a savings plan |
| Volatility / Max DD | 34,5 % / −26,1 %, current −21,1 % | Risk well above a world ETF (if real, see below) |
| Price coverage | 80 % implied prices | **Risk KPIs and monthly returns are not trustworthy yet** |

Two correctness issues block a "stunning" report. Fix them before any design work:

- **Spikes in the hero chart (May–Jul 2026)** and ±18 % months (04/26, 07/26) coincide with trade days and the mixed market/implied stretches. Check them against a known index month before believing them. Likely causes: switching between market and implied price inside one ISIN, and fee-inclusive implied prices. Fix: never mix sources within a holding period (use market for the whole period if available, otherwise implied for the whole period), and use market prices for sold ISINs wherever Yahoo has them. Target implied share: under 20 %.
- **Current drawdown −21 % with value near its high** contradicts the chart. Recheck once pricing is fixed.

Until the implied share is under 20 %, the report shows risk KPIs greyed out with "≈ unzuverlässig".

## 2. What a good ETF performance report looks like (as of Oct 2026)

The established pattern (private-bank client reports, broker annual statements, tools like Parqet, Portfolio Performance and getquin) converges on this:

- **Page 1 answers five questions in 30 seconds.** How much do I have? How much did I earn? Am I better than a simple world ETF? How risky is it? Am I on track?
- **A narrative executive summary**, three to five generated sentences, not just tiles.
- **One hero chart** for wealth over time, with contributions and a benchmark that received the same cashflows.
- **Drill-down below the fold**: allocation, contributors, risk, costs, then goals, then appendix.
- **Market context** is clearly separated from your own numbers, dated and sourced.
- **Health check** with traffic lights against *your own* targets (allocation bands, max position, TER ceiling). It shows deviations, not buy/sell advice.
- **Appendix** for the audit trail: transactions, reconciliation, data quality, methodology.

Your example summary follows this pattern. Three corrections when adapting it:

- "Net of fees" is automatic, because TER is embedded in ETF prices. Only explicit order fees can be shown separately.
- "Currency exposure 55 % USD" is a **look-through** figure (underlying holdings). The trading currency of all four positions is EUR. It needs per-fund metadata (§6).
- "Rebalancing recommended" becomes "Abweichung vom Zielband: Tech +3 pp". The report states the deviation against your configured target and doesn't recommend trades.

## 3. Page blueprint

Three layers: a summary that fits on about 1.5 screens, an analysis section, and a collapsed appendix. Each layer gets a sticky in-page navigation (Überblick · Performance · Risiko · Allokation · Kosten · Ziele · Markt · Anhang).

### Layer 1 — Überblick (above the fold)

**Header band**
- "ETF-Portfolio-Bericht · Stand 05.10.2026"
- Subline: Daten bis 02.10. · Kurse vom 05.10. · Datenqualität ● (green/amber/red dot with tooltip)
- Toggles: Beträge verbergen · Hell/Dunkel · Drucken

**Executive Summary card** (left 1/3) contains generated prose plus 4 headline numbers:

> Ihr Depot steht bei **41.139 €**, davon **8.283 €** Gewinn auf 32.855 € Einzahlungen. Seit Start erzielten Sie **20,4 % p.a.** (XIRR) und liegen **6,3 pp vor** dem FTSE All-World bei identischen Einzahlungen. Das Depot ist stark konzentriert: drei Positionen machen **91 %** aus, Themen-ETFs **34 %**. Im Jahr 2026 lag der Umschlag bei **564 %**.

Sentence rules live in `narrative.py`. Each one is a template plus a condition, for example "only mention benchmark if coverage ≥ 80 % market", or "concentration sentence if top-3 > 60 %". No LLM is needed at runtime.

The four headline tiles are: Depotwert · Gewinn € · Rendite p.a. (XIRR) · vs. Benchmark (Δ pp). Each tile has a sparkline and a "seit / YTD" sub-value.

**Hero chart** (right 2/3), see §4.

**Health check strip**: 6 traffic lights, one line each, against `targets:` in the config:

| Check | Green | Amber | Red |
|---|---|---|---|
| Größte Position | ≤ target_max_position | +5 pp | above that |
| Top-3 | ≤ 60 % | ≤ 80 % | > 80 % |
| Satellite share (thematic/sector) | within band | ±5 pp | outside |
| Gewichtete TER | ≤ 0,25 % | ≤ 0,40 % | > 0,40 % |
| Drawdown aktuell | > −10 % | > −20 % | ≤ −20 % |
| Datenqualität | 0 unresolved, implied < 20 % | implied < 50 % | otherwise |

### Layer 2 — Analyse

**Performance**
- KPI row: TWR seit Start · TWR p.a. · YTD · rolling 1 year · Bester/Schlechtester Monat · Excess return vs benchmark
- Calendar heatmap of monthly returns: years × months plus a YTD column, with a second row per year for the benchmark (small, grey) so beats and misses are visible per month
- Annual bars: portfolio vs benchmark, side by side

**Beitrag (Contribution)**
- Diverging horizontal bar chart: gain € per instrument (realized + unrealized + income), sorted, names not ISINs. Show the top 5 and bottom 5; "weitere 24" goes into `<details>`.
- Waterfall: Einzahlungen → + realisiert → + unrealisiert → + Erträge → − Steuern → Depotwert. This is the single best chart for "where did my money come from".

**Risiko**
- KPI row: Volatilität · Max DD · Akt. DD · DD-Dauer · Sharpe · Sortino · Beta / Korrelation zum Benchmark
- Underwater chart (drawdown over time, portfolio vs benchmark), aligned with the hero chart's time axis
- A risk/return scatter of your positions plus the benchmark plus 3 model portfolios (§5) over the last 12 months. It shows instantly where the portfolio sits.

**Allokation & Diversifikation**
- A treemap by position, nested in core/satellite, instead of the donut
- 100 % stacked bars for region, sector and currency (look-through, with as-of date and coverage %)
- ETF overlap matrix (4×4 at the moment), only if holdings metadata is available
- Cash weight

**Kosten & Aktivität**
- Weighted TER (€ per year: value × TER), explicit fees from crypto/Baader rows, tax drag (VAP + Steuerausgleich net), turnover 12M, trades per month
- One sentence: "Ihr Handel verursachte X € explizite Kosten und Y € Steuern; die laufenden Fondskosten betragen ca. Z €/Jahr."

**Ziele**
- Fan chart: current value plus monthly saving, projected at 4 / 7 / 10 % with a real (inflation-adjusted) toggle; the target line and "on track" marker
- KPIs: Zielvermögen in 10 J · Fortschritt % · benötigte Sparrate · benötigte Rendite · mögliche Monatsentnahme (nominal/real) · Restkapital
- Fix: the current simulator shows "—" on first render. Compute on load.

### Layer 3 — Markt & Vergleich (§5) and Anhang (collapsed)

- Markt & Vergleich: see §5
- Anhang: Transaktionen (filterable), Verkaufsliste, Realisiert je Instrument, VAP-Abgleich, Kursabdeckung, Methodik & Konventionen, data-quality log

Target length: Layer 1 + 2 ≈ 4–5 screens at 1280 px. The appendix is invisible until opened.

## 4. Hero chart v3

Keep what works (value vs contributions vs benchmark), then add the following.

- **Gain band.** Fill the area *between* depot value and contributions: green where above, red where below. This shows the gain € directly and is the most readable element on the page. Drop the full-height blue area fill.
- **Benchmark with identical cashflows** as a dashed line, labelled at its right end ("FTSE All-World: 39.2 T€"). Use direct end-labels for all three lines instead of a legend.
- **Mode toggle:** € Vermögen | Index = 100 (TWR vs benchmark TWR) | Drawdown. Three views, one axis, one card.
- **Range tabs:** 1M · 3M · YTD · 1J · MAX, plus a brush/zoom on the x-axis.
- **Event markers.** Small ticks on the x-axis for deposits ≥ 2.000 €, and dots for "switch" days (sells > 3.000 €). The tooltip lists the trades of that day by name.
- **Annotations:** an all-time-high marker, and the current drawdown shown as a shaded bracket from the peak to today.
- **Estimated stretches** are drawn with a lighter stroke, with a legend note "Kurs geschätzt".
- **Unified tooltip:** date · Depotwert · Einzahlungen · Gewinn € · Benchmark · Δ.
- **Axes:** compact € (0 / 10 T / 20 T…), month ticks, and the y-axis starting at 0 in € mode.
- **Height:** 360 px desktop, 240 px mobile.

## 5. Market context, comparison, news, trends

This is the one part that is not derived from your CSV. Three rules apply:

- It is **separated visually** (its own section, "Marktumfeld — Stand <date>, Quellen unten").
- It is **sourced and dated**.
- It **never sends your holdings or amounts out**. Only public tickers and feed URLs are fetched.

### 5.1 "Was andere investieren": model portfolios (deterministic, recommended)

Compare your TWR, volatility and max DD against simulated reference portfolios run on the same cashflows:

| Model | Composition (config) |
|---|---|
| Einfach-Welt | 100 % FTSE All-World |
| Klassiker 70/30 | 70 % MSCI World + 30 % EM |
| Ausgewogen 60/40 | 60 % All-World + 40 % € government bonds |
| Ihr Ziel-Mix | your `targets.allocation` |

The output is a comparison table (Rendite p.a., Vola, Max DD, end wealth) plus the risk/return scatter in §3. This answers "what would a typical passive investor have now" with real numbers instead of anecdotes. All models are config-driven ETF tickers, cached like the other prices.

### 5.2 Popularity and flows (optional, manual)

Broker "most saved ETFs" lists and fund-flow rankings are not available as stable free APIs, and scraping them is fragile. Use `context/popular.yaml` instead: a hand- or AI-maintained list (name, ISIN, rank, source URL, as-of). The report shows a "Beliebte Sparplan-ETFs" table and marks the ones you hold.

### 5.3 News and trends: build-time digest

There are two sources, and both are rendered into the static HTML at build time:

- **RSS/Atom feeds** listed in `config.yaml → news.feeds`, for example your broker's news, ETF-portal news and the issuer press pages for your four funds. These are fetched with `--offline` fallback to cache, filtered by keywords (fund names, index names, "Semiconductor", "Quantum", "MSCI World"), and limited to the last 30 days, at most 8 items. Each item shows title, source, date and link. Use the stdlib `xml.etree` parser; no dependency is needed.
- **Monthly AI briefing.** `context/YYYY-MM.md` is written by you with pi or Claude using web search: a 5-bullet market summary, sector moves relevant to your holdings, rate/inflation backdrop, and events ahead. It always ends with a source list. The report renders the newest file via a tiny Markdown→HTML step (`markdown-it-py`, or the `markdown` package). The prompt template lives in `context/PROMPT.md`, so every month produces the same structure.

Display: a two-column card. The left column is the "Marktlage" briefing (with date and sources); the right is "Nachrichten zu Ihren Positionen" (feed items grouped by holding). If either is older than 45 days, it shows an amber "veraltet" badge.

Out of scope: social sentiment and live data in the browser. The file must work offline and not phone home when opened.

  short: finanzen.net MSCI World
  ticker: FINZ.DE
  class: ETF
  role: core            # core | satellite
  ter: 0.0005           # verify on factsheet

## 8. Visual design system

- **Tone:** calm, editorial and print-like, closer to an annual report than a trading app. Use one accent colour; green/red only for gain/loss, always with a sign or arrow.
- **Type:** system font stack. Use tabular figures (`font-variant-numeric: tabular-nums`) for all numbers. Scale: 32 / 20 / 15 / 13 px.
- **Grid:** a 12-column grid with max width 1200 px. Cards have 16 px radius and a hairline border instead of heavy shadows.
- **Numbers:** compact in tiles (41,1 T€) and exact in tooltips and tables. Percent with one decimal; percentage points written as "pp".
- **Charts:** one library throughout. Vendor ECharts (inlined, offline) now that the chart count grows to about 10: heatmap, treemap, waterfall, scatter and brush/zoom come free, and so does a dark theme. The hand-rolled SVG has reached its limit.
- **Dark mode:** CSS variables plus `prefers-color-scheme` and a manual toggle; chart themes are switched with it.
- **Print/PDF:** Layer 1 on page 1 and Layer 2 on pages 2–3, with the appendix expanded; navigation and toggles are hidden.
- **Mobile:** tiles 2×2, a 240 px hero, and tables that scroll horizontally with a sticky first column.

## 11. Acceptance

- A first-time reader can state value, gain, return p.a., benchmark gap and the main risk within 30 seconds, from the first screen only.
- No KPI is shown without a period. Every estimated KPI carries "≈", and every external fact carries a date and source.
- The hero chart has no single-day jumps above 5 % that a benchmark doesn't share (an automated check in data quality).
- The report is complete offline, and opening the file makes zero network requests.
- Layer 1 + 2 ≤ 5 screens at 1280 px; print is ≤ 4 pages without the appendix.
- `grep -E 'DE[0-9]{20}' out/*.html` is empty, and no amounts or quantities appear in any outbound request.
